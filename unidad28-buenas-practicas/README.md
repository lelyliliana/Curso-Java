# Unidad 28 — Buenas prácticas y refactorización

## Nombres
Expresan intención.

## Métodos
Pequeños y cohesionados.

## Clases
Responsabilidades claras.

## Duplicación
Refactoriza cuando existe conocimiento repetido, no por obsesión con eliminar cada línea similar.

## Comentarios
Explican decisiones o contexto; no traducen literalmente el código.

## Dependencias
Programa contra contratos cuando mejora desacoplamiento.

## Refactorización
Cambia estructura preservando comportamiento; las pruebas ayudan a comprobarlo.

## Reto
Toma código deliberadamente difícil de mantener y refactorízalo en pasos pequeños con pruebas.
